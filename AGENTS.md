## 1. Контекст предметної області

Система призначена для автоматизації фізико-механічних випробувань зразків матеріалів на розрив/стиск.
Машина складається з:
1. **Нерухомої та рухомої траверси**, між якими затискається випробувальний зразок (розміри: $h$ — товщина, $w$ — ширина, $l$ — початкова довжина $L_0$).
2. **Асинхронного електродвигуна** з черв'ячним/гвинтовим редуктором для переміщення траверси.
3. **Частотного перетворювача Delta VFD**, що регулює швидкість та напрямок ходу траверси.
4. **Тензометричного датчика**, закріпленого на траверсі, який сприймає розривне зусилля.
5. **Вагового індикатора ХК 3118 Т16**, який оцифровує сигнал тензодатчика і передає його в ПК по RS-232.
6. **Датчика видовження (переміщення траверси)**, який передає абсолютне або відносне видовження $\Delta L$ по RS-232.

## 2. Апаратні інтерфейси та протоколи обміну

### 2.1. Ваговий термінал Keli XK3118-T16 (Канал Force)
* **Фізичний рівень**: RS-232 (або перетворювач USB-RS232).
* **Параметри UART**: 9600 bps, 8 Data Bits, 1 Stop Bit, No Parity (`8N1`).
* **Режим передачі**: неперервний стрім ASCII-символів (Continuous Mode).
* **Формат посилки XK3118**:
  * Зазвичай передає кадри виду: `[STX / =][± / пробіл][6-7 символів ваги з десятковою крапкою][CR][LF]`.
  * *Поточна реалізація:* [`SerialPorts::getSeria()`](file:///D:/temp/stretching_machine/TensileTest/serialports.cpp#L92) очікує рядок і виконує `ba1.mid(1, 7).toDouble()`.

### 2.2. Тензометричні датчики (Конфігурація вимірювання)
У системі застосовуються 3 взаємозамінні датчики (**OAP quality**):
| Модель датчика | Номінальне навантаження | Гранична сила (Н) | Рекомендований поріг старту випробування | Призначення |
| :--- | :--- | :--- | :--- | :--- |
| **DEF 50 kg** | 50 кг | ~490 Н | 0.05–0.2 кг (~0.5–2 Н) | Тонкі плівки, гума, текстиль |
| **DEF 500 kg**| 500 кг | ~4 900 Н (4.9 кН) | 0.5–1.0 кг (~5–10 Н) | Пластики, шнури, композити |
| **PST-3t** | 3 000 кг (3 т) | ~29 420 Н (29.4 кН)| 2.0–5.0 кг (~20–50 Н) | Метали, сталевий дріт, арматура |

> [!IMPORTANT]
> **Критична вимога безпеки**: У коді обов'язково має бути реалізований **програмний захист від перевантаження (Emergency Overload Stop)**: при досягненні 105% від номіналу активного датчика система зобов'язана негайно надіслати команду `STOP` на Delta VFD, щоб запобігти механічному руйнуванню датчика!

### 2.3. Частотний перетворювач Delta VFD (Канал Frequency / Motor Control)
* **Фізичний рівень**: RS-485 (2-провідний Modbus по інтерфейсу напівдуплекс).
* **Параметри UART**: 9600 bps, 7 Data Bits, 2 Stop Bits, No Parity (`7N2`) (або 7, Even, 1).
* **Протокол**: **Modbus ASCII**.
* **Структура кадру Modbus ASCII**:
  ```text
  : [Slave: 2 hex] [Func: 2 hex] [Address: 4 hex] [Data: 4 hex] [LRC: 2 hex] \r\n
  ```
* **Адреси та команди (Delta VFD-M / VFD-EL / VFD-E)**:
  * Slave ID за замовчуванням: `01`
  * Функція запису в один регістр: `06`
  * Регістр `2000H` (Керування приводом):
    * `0001H` — Стоп (`:010620000001D8\r\n`)
    * `0002H` — Пуск (`:010620000002D7\r\n`)
    * `0010H` — Обертання вперед (рух траверси вгору / натяг)
    * `0020H` — Реверс (рух траверси вниз / повернення)
  * Регістр `2001H` (Завдання вихідної частоти):
    * Значення = частота в Гц * 100 (наприклад, 50.00 Гц = `5000` = `0x1388`).

## 4. Карта виявлених багів та технічного боргу

### 1. `SerialPorts::getSeria()`
- [ ] **Несинхронне читання**: `readLine()` повертає неповні фрагменти, якщо пакет ще не надійшов повністю. Потрібно перейти на буферизацію через сигнал `QSerialPort::readyRead` або перевірку `canReadLine()`.
- [ ] **Хибний `try/catch (QString)`**: `QString::toDouble()` повертає `0.0` і `bool ok`, а не викидає винятки C++.
- [ ] **Застрягання на `lastResult`**: при `result == 0` значення перезаписується попереднім, унеможливлюючи повернення показів до 0.

### 2. `VFD2::lrcCount` та генерація Modbus ASCII
- [ ] **Помилка переповнення суми**: при `sum > 256` алгоритм дає некоректний результат. Має бути `quint8 lrc = static_cast<quint8>(-sum);`.
- [ ] **Втрата лідируючого нуля**: шістнадцятковий запис байта обов'язково повинен містити 2 символи (`QString("%1").arg(lrc, 2, 16, QChar('0')).toUpper()`).

### 3. Робота з тензодатчиками та порогом сили
- [ ] **Жорстко зашитий поріг `f > 5`**: ламає роботу з датчиком 50 кг. Необхідно зробити поріг адаптивним відповідно до обраного датчика.
- [ ] **Відсутність вибору активного датчика** (50 кг / 500 кг / 3 т) в UI.
- [ ] **Відсутність тарування (Tare / Zero)** для компенсації ваги захватів.
- [ ] **Одиниці вимірювання**: перехід з кг на Н/кН ($F = m \cdot g$).

### 4. Продуктивність (GUI Thread & SQLite)
- [ ] Кожні 100 мс виконується одиночний `INSERT` у SQLite прямо в GUI-потоці. Потрібно групувати записи через транзакції (`db.transaction()` / `db.commit()`) або винести роботу з БД та портами у фоновий Worker.
